## 6. 인터랙션 (실측)

1. **스크롤 리빌이 전 섹션에 걸려 있다.** 프로그램적으로 스크롤을 점프시키면 섹션 제목만 보이고 본문·이미지는 **끝까지 안 나타난다.** 뷰포트에 실제로 진입해야 렌더된다. → 어제의 정적 풀페이지 캡처(`ref-agr-full-16000.png`)에 빈 구간이 섞여 있었을 가능성이 높다.
2. **섹션 헤더 고정 패턴**: 좌측에 90px 대제목 + 우측 상단 첨자로 개수 `(6)` `(5)`, 그리고 **오른쪽 끝에 14px 3줄 설명 블록**. 가운데는 통째로 비운다.
3. **FLOW = 4열 계단식**. DISCOVER→DESIGN→BUILD→LAUNCH로 갈수록 각 열의 내용이 아래로 내려가는 대각선 배치. 각 열에 퍼센트(25/50/75/100%)와 **길이가 다른 진행 바**, 열 사이 세로 헤어라인.
4. **수치는 0에서 카운트업**. 정지 상태 DOM에는 `0+`로 남아 있다.
5. **버튼 텍스트 슬라이드 교체** (§4).
6. 비대칭 3분할 반복: `좌측 14px 라벨 / 중앙 26px 진술 / 우측 14px 번호(01, 02)`.

## 8. 구현 전 결정 필요 (컨펌 대상)

### 8-1. 폰트 충돌
AGR은 **Inter Display / Inter**를 쓴다. `SYSTEM_CORE.md` §9.3은 Inter를 금지 폰트로 명시한다.
- 안 A: 금지 규칙 유지 → Geist(영문) + Pretendard(한글). Geist는 Inter와 골격이 가까워 90px/-3.3px 대비는 재현 가능
- 안 B: `/ax` 한정으로 Inter Display 허용 (레퍼런스 정확도 우선)

### 8-2. 히어로 워드마크 기법
- 안 A: **WebGL 셰이더로 실제 구현** — 텍스트를 마스크로 쓰고 그 안에 흐르는 유체 노이즈를 렌더 (AGR 기법 복제)
- 안 B: CSS 그라디언트 애니메이션으로 대체 → **어제 실패본과 같은 선택**이 됨

### 8-3. 이미지 재료
AGR 페이지의 색은 전부 실제 작업물 사진에서 나온다. TOMOB AX는 실제 AX 사례 이미지가 없다.
- 안 A: 기존 웹 제작 포트폴리오(FLOWING, SOMEMOOD, LAFCO, LAiKiN)의 실제 화면을 세로형 629×679 목업으로 재촬영/재구성
- 안 B: GPT 생성 이미지 계속 사용 → 어제 실패 요인 중 하나
- 안 C: 이미지 없이 텍스트·수치·선만으로 구성 (AGR의 시각 밀도는 포기)
