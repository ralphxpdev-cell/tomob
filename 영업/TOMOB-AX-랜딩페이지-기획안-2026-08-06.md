# TOMOB AX 랜딩페이지 기획안

- 작성일: 2026-08-06
- 목표: ‘AX를 소개하는 회사 홈페이지’가 아니라, 작은 기업 대표가 자기 회사의 운영 병목을 제출하게 만드는 수주 랜딩
- 기준 레퍼런스: 조슈아앤컴퍼니의 팀·프로젝트 신뢰 구조, PASSOME의 웹+시스템 통합, 처음AX의 작은 시작·가격 구조
- 현재 단계 원칙: 없는 고객·성과를 꾸미지 않고, TOMOB가 이미 가진 제작 역량과 2인 역할 구조를 신뢰 자산으로 사용한다.

---

## 1. 이 랜딩이 팔아야 하는 것

AX라는 개념을 팔지 않는다. 첫 구매 상품은 `채용 전 업무점검`이다.

대표가 직원을 더 뽑으려는 순간에는 대개 다음 중 하나가 발생한다.

- 문의가 늘었는데 확인과 배분이 늦다.
- 견적서·보고서·정산 자료를 매번 다시 만든다.
- 고객 정보가 카톡·메일·엑셀에 흩어진다.
- 같은 내용을 여러 시스템에 반복 입력한다.
- 대표나 핵심 직원만 처리할 수 있는 일이 계속 쌓인다.

랜딩의 역할은 방문자가 `AI가 필요하다`고 느끼게 하는 것이 아니라, `사람을 뽑기 전에 지금 하는 일의 구조부터 보여줘야겠다`고 느끼게 하는 것이다.

### 핵심 전환 목표

`채용 전 업무점검 신청` 제출

### 제출받을 정보

- 회사명과 업종
- 직원 수
- 추가 채용을 고민 중인 업무
- 해당 업무 담당자 수
- 반복 주기와 1회 소요시간
- 현재 사용하는 도구
- 연락처

## 2. 포지셔닝

### 회사 정의

> TOMOB는 작은 기업의 반복 업무를 진단하고, 실제로 운영되는 웹 시스템과 자동화로 바꾸는 독립 AX 스튜디오입니다.

### 고객에게 보여줄 한 문장

> 사람을 더 뽑기 전에, 일이 새는 구조부터 바꿉니다.

### 구체적인 약속

> 문의, 고객관리, 견적, 보고처럼 반복되는 업무 하나를 골라 실제 데이터로 작동하는 흐름을 만듭니다.

### 타깃

- 5~50명 규모의 작은 기업
- 대표가 아직 실무를 직접 처리하는 회사
- 운영·영업·관리 인력의 추가 채용을 고민하는 회사
- SaaS 하나로 해결되지 않아 엑셀·카톡·메일 사이를 사람이 연결하는 회사

### 지금 제외할 타깃

- 전사 ERP 교체가 필요한 회사
- 자체 AI 모델 개발이 필요한 회사
- 대기업 폐쇄망·보안 인증이 선행돼야 하는 프로젝트
- 단순 강의나 임직원 AI 교육만 원하는 회사

## 3. 페이지 전체 서사

```text
채용을 고민하는 장면
→ 사람이 메우고 있는 병목 자각
→ TOMOB가 바꾸는 실제 업무 흐름 확인
→ 작은 범위로 검증할 수 있다는 안심
→ 만드는 사람과 방식 확인
→ 현재 증거 확인
→ 업무점검 신청
```

조슈아처럼 `Learn / Build / Run` 구조는 사용하되, 아직 교육 레퍼런스가 없는 TOMOB는 `Find / Build / Run`으로 변형한다.

- Find: 일이 새는 지점과 자동화 가능 범위 진단
- Build: 실제 업무 하나를 시스템으로 구축
- Run: 운영 중 오류·예외·변경을 계속 관리

## 4.3 Pain — ‘인건비 절감’을 직접 말하지 않고 채용 원인을 보여줌

### 제목

> 정말 사람이 부족한 걸까요,
> 아니면 일이 사람에게 너무 많이 기대고 있는 걸까요?

### 선택형 진단 항목

- 문의가 오면 누군가 읽고 담당자에게 다시 전달한다.
- 견적서나 보고서를 매번 복사해서 새로 만든다.
- 고객 정보가 카톡, 메일, 엑셀에 나뉘어 있다.
- 같은 데이터를 두 번 이상 입력한다.
- 담당자가 쉬면 업무 상태를 아무도 모른다.
- 일을 늘리려면 사람부터 더 뽑아야 한다.

### 섹션 마무리

> 세 개 이상 해당된다면, 채용보다 먼저 업무 흐름을 점검할 가치가 있습니다.

CTA: `우리 회사 병목 확인하기`

## 4.4 What We Change — 자동화 예시를 기능이 아니라 전후 흐름으로 설명

### 제목

> AI를 도입하는 게 아니라,
> 매일 반복되는 흐름을 다시 만듭니다.

### 예시 1: 문의에서 후속 연락까지

Before:
`카톡·메일 확인 → 엑셀 입력 → 담당자 전달 → 후속 연락 기억`

After:
`문의 자동 수집 → 내용 분류 → 고객 DB 저장 → 담당자 알림 → 미응답 재알림`

측정할 값:
`최초 응답시간 / 누락 건수 / 수기 입력시간`

### 예시 2: 견적과 제안서 작성

Before:
`요청사항 정리 → 이전 파일 검색 → 문서 복사 → 금액 수정 → PDF 발송`

After:
`요청 정보 입력 → 템플릿 자동 구성 → 담당자 검수 → PDF 생성·기록`

측정할 값:
`작성시간 / 수정 횟수 / 발송까지 걸린 시간`

### 예시 3: 주간 보고와 정산

Before:
`여러 파일 취합 → 수치 정리 → 그래프 생성 → 보고서 작성`

After:
`데이터 자동 수집 → 형식 통일 → 요약·이상값 표시 → 보고서 초안 생성`

측정할 값:
`취합시간 / 오류 건수 / 보고 주기`

### 주의

이 세 가지는 ‘구축 완료 사례’로 표현하지 않는다. `TOMOB가 우선 진단하는 업무`로 명시한다. 실제 사례가 생기면 같은 위치를 Before/After 사례로 교체한다.

## 4.6 Process — Find / Build / Run

### 제목

> 진단하고, 만들고, 운영합니다.

### 01 Find — 업무를 먼저 이해합니다

- 현재 흐름과 예외 상황 확인
- 자동화할 일과 사람이 판단할 일 구분
- 성공 기준 합의

### 02 Build — 작동하는 업무 하나를 만듭니다

- 기존 도구를 가능한 유지
- 필요한 화면·DB·자동화 연결
- 실제 데이터로 한 사이클 검증

### 03 Run — 회사 안에 남게 운영합니다

- 담당자가 볼 수 있는 로그와 관리 화면
- 장애·API 변경·예외 대응
- 운영 매뉴얼과 지속 개선

### 기간 표기

- 점검: 1~3영업일
- 첫 파일럿: 범위에 따라 2~4주
- 운영: 월 단위

`10영업일 완성`은 기술 범위가 검증되기 전까지 메인 약속으로 사용하지 않는다.

## 4.7 Proof — 없는 AX 사례 대신 증거의 종류를 분리

### 제목

> 말보다, 실제로 만든 것으로 설명합니다.

### 초기 공개 구조

#### A. 기존 제작 프로젝트

- 실제 고객의 웹사이트·인터랙션·관리 기능
- TOMOB가 직접 설계하고 구현한 범위
- 현재 라이브 링크 또는 화면

#### B. AX 데모

- TOMOB 내부 영업 업무 자동화
- 문의 접수 → DB 저장 → 알림 → 상태관리
- 샘플 데이터임을 명확히 표시

#### C. 첫 파일럿 모집

> 첫 3개 파트너사의 업무를 우선 조건으로 구축하고, 측정 결과를 함께 사례화합니다.

할인이나 무료보다 다음 교환조건을 명확히 한다.

- 실제 업무 담당자의 피드백 제공
- 도입 전후 시간 측정
- 익명 또는 실명 사례 공개 협의

### 사례가 생긴 뒤 카드 필수 항목

- 고객 업종과 규모
- 이전 업무 방식
- 구축한 흐름
- 처리 대상 규모
- 도입 전후 수치
- 사람이 계속 판단하는 부분
- 사용 기간

로고만 늘어놓는 방식은 사용하지 않는다.

### 구축 파트너

## 4.10 FAQ — 구매 불안 해소

### 어떤 업무부터 자동화해야 하나요?

반복 빈도가 높고, 처리 기준이 있으며, 현재 시간이 측정되는 업무부터 봅니다. 처음부터 회사 전체를 바꾸지 않습니다.

### 직원을 줄이기 위한 서비스인가요?

해고를 목적으로 설계하지 않습니다. 채용을 결정하기 전 현재 인력이 반복 작업에 쓰는 시간을 줄이고, 더 중요한 업무에 투입할 수 있는지 확인합니다.

### 기존에 쓰는 엑셀이나 카톡을 바꿔야 하나요?

가능하면 기존 도구를 유지하고 그 사이의 전달·입력·알림부터 연결합니다. 도구 교체가 더 경제적일 때만 별도로 제안합니다.

### AI가 잘못 처리하면 어떻게 하나요?

금액, 발송, 계약, 고객 응대처럼 위험한 단계에는 사람 승인과 실행 로그를 둡니다.

### 비용은 어떻게 정해지나요?

업무 수, 연결할 도구, 데이터 상태, 예외처리, 관리자 화면 필요 여부에 따라 달라집니다. 첫 파일럿은 업무 하나를 기준으로 범위를 고정해 견적합니다.

## 8. 확정이 필요한 세 가지

1. 현재 TOMOB 메인 사이트를 AX 중심으로 교체할지, `/ax` 독립 랜딩으로 시작할지

3. 첫 집중 업무를 `문의·고객관리`, `견적·제안서`, `보고·정산` 중 하나로 좁힐지

### 권장안

- 기존 포트폴리오 사이트는 유지하고 `/ax` 독립 랜딩으로 먼저 검증
- 파일럿 가격은 `200만 원부터` 공개
- 첫 집중 업무는 기존 웹 제작과 바로 연결되는 `문의 접수→고객 DB→담당자 배정→후속 연락`으로 시작

이 안은 TOMOB가 이미 가진 웹 구축 역량을 가장 빠르게 AX 계약과 사례로 바꿀 수 있다.
