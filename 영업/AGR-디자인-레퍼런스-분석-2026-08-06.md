# AGR Studio 디자인 레퍼런스 분석

- 기준 사이트: https://agr.studio/
- 확인일: 2026-08-06
- 원본 캡처: `ref-agr-full-16000.png` (1440 × 16000)
- 적용 대상: TOMOB 독립 AX 랜딩 `/ax`
- 상태: 디자인 해석 컨펌 대기 — 컨펌 전 코드 수정 금지

## 1. 레이아웃 구조

- 전체 레이아웃: 흰 배경의 단일 세로 흐름. 콘텐츠는 좌우 약 40px 안쪽의 거의 풀폭 컨테이너를 사용한다.
- 히어로: 상단 중앙 초대형 워드마크가 화면 폭 대부분을 차지하고, 설명과 CTA는 그 아래 매우 작게 중앙 정렬된다.
- 프로젝트: 동일 폭의 2열 이미지 그리드. 이미지가 설명보다 압도적으로 크며 각 프로젝트명과 업종은 이미지 바로 아래 한 줄로 붙는다.
- 소개·수치: 좌측의 작은 섹션 라벨, 중앙의 본문, 하단의 큰 숫자를 비대칭으로 배치한다.
- 서비스·프로세스: 별도 카드 장식을 거의 쓰지 않고 선, 번호, 텍스트, 한 장의 넓은 비주얼로 구성한다.
- 후기·상품: 필요한 구간에서만 얇은 테두리의 카드 그리드를 사용한다.
- 푸터 전 CTA: 화면 중앙에 짧은 문장을 놓고 위아래로 매우 큰 여백을 둔다.
- 푸터: 히어로의 대형 워드마크를 반복해 처음과 끝을 연결한다.

## 2. 타이포그래피

- 기본: 굵은 산세리프와 작은 산세리프만 사용한다. 세리프·이탤릭·장식용 영문 폰트는 없다.
- 히어로 워드마크: 데스크톱 기준 약 150~180px 체감 크기, 한 줄, 화면 폭 약 94% 점유.
- 주요 섹션 제목: 약 72~88px 체감 크기의 대문자 볼드. `PROJECTS`, `SERVICES`, `FLOW`, `ENGAGEMENTS`처럼 짧다.
- 본문: 18~22px 수준으로 비교적 작고 줄 길이를 짧게 제한한다.
- 메타 정보: 11~13px 수준의 작은 대문자·숫자를 사용한다.
- 위계 방식: 색이나 그림자보다 글자 크기의 큰 대비로 위계를 만든다.

## 3. 여백과 간격

- 좌우 여백: 약 2.5~3vw. 프로젝트 이미지는 컨테이너 폭을 거의 전부 사용한다.
- 섹션 간격: 약 140~220px 체감. 섹션 사이에는 매우 옅은 1px 구분선을 둔다.
- 히어로: 상단 내비게이션부터 워드마크까지는 짧고, 워드마크 아래 설명은 밀착된다.
- 프로젝트 그리드: 열 간격 약 20~24px, 행 간격 약 30~40px.
- 푸터 전 CTA: 다른 구간보다 훨씬 큰 빈 공간을 확보해 호흡을 만든다.

## 4. 색상과 이미지

- 기본 팔레트: 백색 `#FFFFFF`에 가까운 배경, 흑색 텍스트, 매우 옅은 회색 선.
- 고유 색상은 UI가 아니라 프로젝트 이미지와 대형 워드마크의 블루 그라디언트에 집중한다.
- 버튼은 검정 캡슐형이지만 크기가 작아 시각적 주인공이 되지 않는다.
- 프로젝트 이미지는 모두 고품질 완성본이며, 장식용 AI 추상 이미지가 작업 증거를 대신하지 않는다.

## 5. 특징적 패턴

1. **워드마크가 곧 히어로**: 별도 3D 오브젝트 대신 브랜드 이름 자체를 가장 큰 비주얼로 쓴다.
2. **작업물이 페이지의 색을 만든다**: UI는 흑백으로 물리고 사례 이미지에 색을 맡긴다.
3. **2열 증거 보드**: 사례를 작은 카드 설명이 아니라 큰 이미지의 연속으로 보여준다.
4. **번호와 선으로 만든 편집 리듬**: `01`, `02`, 퍼센트, 괄호 숫자, 얇은 선이 시스템감을 만든다.
5. **첫 화면과 푸터의 반복**: 대형 로고를 양끝에 배치해 긴 페이지를 하나의 프레임으로 닫는다.

## 6. TOMOB AX 적용 해석안

### 그대로 가져올 것

- 흰 배경 중심의 절제된 편집 레이아웃
- 초대형 `TOMOB AX` 워드마크 히어로
- 큰 제목 + 작은 설명의 극단적 크기 대비
- 2열 사례/업무 시나리오 그리드
- 번호, 진행률, 얇은 선으로 구성한 Find → Build → Run 프로세스
- 작은 검정 CTA와 충분한 여백
- 푸터의 대형 워드마크 반복

### TOMOB에 맞게 바꿀 것

- AGR의 프로젝트 포트폴리오 자리는 실제 AX 사례가 없으므로 `자동화 전/후 업무 화면` 또는 `파일럿 시나리오`로 구성하되, 가짜 고객 실적으로 표현하지 않는다.
- AGR의 블루 그라디언트 로고는 복제하지 않고 TOMOB의 블루 `#2595FF`를 제한적으로 사용한다.
- 서비스 5종 대신 `업무 발견 / 자동화 구축 / 운영 개선`의 3단 구조로 단순화한다.
- 에이전시 일반론보다 `채용하기 전에, 반복 업무부터 줄입니다`라는 기존 AX 핵심 메시지를 유지한다.

### 제외할 것

- 현재 `/ax`의 형광 라임 중심 팔레트
- 거대한 원형 궤도·AI 추상 그래픽
- 의미 없는 기능 카드 반복
- 근거 없는 성과 숫자와 고객 로고
- AGR 문구·프로젝트 이미지·브랜드 표현의 직접 복제

## 7. 구현 전 컨펌 대상

제안하는 최종 방향은 **Genesis의 폰트·접근성 원칙은 유지하되, 시각 아키타입을 AGR식 흑백 에디토리얼로 교체**하는 것이다. TOMOB 블루는 워드마크와 일부 상태 표시에만 제한하고 전체 배경은 흰색으로 전환한다.

컨펌 후 아래 패턴을 최소 4개 구현한다.

- 초대형 워드마크 히어로
- 2열 증거 보드
- 비대칭 라벨/본문/수치 구성
- 번호와 얇은 선 기반 서비스·프로세스
- 큰 여백의 중앙 CTA
- 워드마크 반복 푸터
